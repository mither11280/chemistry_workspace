# 实测：132 题起始批次

测试日期：2026-10-27。当前 Mac、Python 3.9、PyMuPDF 1.26.5。真实样本为 2024–2026 March 的 120 道 MCQ 和 12 道结构题。未清空操作系统文件缓存，结果只代表当前环境；不据此推断大型题库或 Windows 性能。

## 存储

| 项目 | 实测 |
|---|---:|
| 旧题库（原卷 + 每题 PDF + JSON） | 31.45 MB |
| 其中独立题目/答案 PDF | 22.20 MB |
| 新架构原始 PDF（含考纲） | 8.61 MB |
| 公共坐标 JSON + manifest | 0.28 MB |
| SQLite（包含本机全文和答案） | 0.61 MB |
| 新核心总计，无缓存 | 9.50 MB |
| 132 题首块 WebP 缓存 | 3.13 MB |
| 新核心 + 上述缓存 | 12.64 MB |

无缓存相较旧结构减少 69.8%。以上不包含刻意保留的旧题库、迁移备份、个人作业和导出。它们在本机没有被自动删除，因此目前项目总磁盘占用不会自动下降到表中数字。缓存不影响正式 PDF 内容。

## 加载和查询

| 项目 | 实测 |
|---|---:|
| 旧 JSON 读取和 ID 字典（5 次中位数） | 1.01 ms |
| 新 SQLite 首次校验建库 | 67.80 ms |
| 新现有索引加载（5 次中位数） | 56.70 ms |
| 首次验证全部源文件哈希和几何 | 79.91 ms |
| 全部本机文字/MCQ 提取 | 649.08 ms |
| SQL 知识点 + 年份查询（20 次中位数） | 0.45 ms |

旧 JSON 读取没有新架构的 schema 校验、完整性校验和 SQL 建库工作，不可据此说新启动更快。首次导入包含原卷校验和本机文字提取；现有目录重启不会重新提取全部正文。测量不包含界面首次绘制或 Swift 窗口启动。

## 预览

| 题目首块 | 旧独立 PDF → PNG | 原卷坐标 → WebP（无缓存） | WebP 命中 |
|---|---:|---:|---:|
| 2025 P1 Q3 | 12.34 ms | 22.73 ms | 0.56 ms |
| 2025 P2 Q4 | 17.16 ms | 38.47 ms | 0.57 ms |

各 5 次中位数。两种编码不同：WebP 首次编码更慢，不能声称所有首次预览都提速；缓存命中后约 0.6 ms。为所有 132 题建立首块缓存共 3.16 s。实际 UI 按需生成，不在首次启动全量渲染。

## 20 题作业

固定 16 道 2025 P1 + 4 道跨 2024–2026 年的 P2 大题，含原卷参考附录；各导出 3 次取中位数。新旧都使用当前同一分页引擎，只替换正文来源（旧独立 PDF / 新原卷坐标），避免用不同排版功能冒充存储性能差异。

| 项目 | 旧独立 PDF | 新坐标方式 |
|---|---:|---:|
| 学生卷耗时 | 359.88 ms | 317.95 ms |
| 学生卷文件大小 | 0.52 MB | 0.50 MB |
| 答案卷耗时 | 未单独测旧版 | 256.47 ms |
| 答案卷文件大小 | 未单独测旧版 | 0.61 MB |

新学生卷约 503 KB，不假定 clip 一定让 PDF 变小。show_pdf_page 仍可复制可见区域之外的页面资源；不把这些 PDF 当作脱敏产物。测试中原创纯矢量示例输出无图片；真实卷本身含的位图资源仍会保留，不会将整题强制栅格化。

复测：保留旧题库时运行 `python scripts/benchmark_bank.py --legacy /path/to/old-bank`。机器可读数据为 `benchmark-results.json`。本次另对 120 个本机提取 MCQ 字母与旧 metadata 逐项对照，120 个一致；这不替代对原卷逐题独立复核。
